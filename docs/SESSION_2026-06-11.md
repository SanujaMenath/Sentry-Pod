# Session 2026-06-11 — Troubleshooting: Frontend Stack Bugs & sentry-ansible Pull Error

## Overview

Three issues were identified and fixed across both the host/frontend dev stack and the podman container stack: (1) the syslog intelligence card showed stale data in the frontend dev server because the backend (uvicorn + syslog-ng) was not running, (2) the `/ai-chat` page rendered a white screen due to a missing `Play` icon import after a codebase refactor, and (3) playbook execution failed with a registry pull error for `localhost/sentry-ansible:latest`. An operational prerequisite for the frontend dev stack was also documented.

## What Changed

### Modified
- `frontend/src/components/PlaybookSuggestions.jsx` — added missing `Play` import from `lucide-react` (used on line 38 but only `Zap` was imported)
- `command-center/src/components/PlaybookSuggestions.jsx` — same fix applied to keep directories in sync
- `watchman/app/services/playbook_service.py` — added `--pull=never` to all 4 podman command builders (`get_podman_command`, `run_drift_analysis`, `run_baseline_collection`, `run_baseline_refresh`) to prevent spurious registry lookups
- `watchman/scripts/container_manager.py` — added `podman save` step in `_build_ansible()` to export image as `watchman/sentry-ansible.tar`; reordered `build all` to build ansible first so the tar is available when watchman is built
- `watchman/scripts/entrypoint.sh` — added `/app/sentry-ansible.tar` as a fallback load location alongside `/tmp/sentry-ansible.tar`
- `.gitignore` — added `watchman/sentry-ansible.tar` to exclude the generated tar from version control

## Architecture

```
Pre-fix podman stack playbook execution:
  Browser -> /playbooks/execute-stream API -> playbook_service.py
    -> podman run localhost/sentry-ansible (--pull=missing default)
    -> image not found in container's podman storage
    -> tries https://localhost/v2/ (registry pull) -> FAILS

Post-fix podman stack playbook execution:
  Browser -> /playbooks/execute-stream API -> playbook_service.py
    -> podman run --pull=never localhost/sentry-ansible
    -> image loaded at startup via entrypoint.sh from /app/sentry-ansible.tar
    -> local image used -> SUCCEEDS
```

## File-by-File Detail

### 1. `playbook_service.py`
All four podman command-building functions changed from `["podman", "run", "--rm"]` to `["podman", "run", "--rm", "--pull=never"]`. The default `--pull=missing` policy causes Podman to attempt a registry pull when a local image is not found in its storage — problematic when running inside the watchman container where the ansible image lives in a tar file rather than native podman storage.

### 2. `container_manager.py`
- `_build_ansible()` now runs `podman save -o ...` after `podman build`, placing `sentry-ansible.tar` in the watchman directory. The tar is picked up by the Dockerfile's `COPY . .` when the watchman container is built.
- `build("all")` order changed: ansible built first, then compose. This ensures the tar exists before the watchman image is baked.

### 3. `entrypoint.sh`
Changed from a single `if [ -f /tmp/sentry-ansible.tar ]` check to a `for tarfile in /tmp/sentry-ansible.tar /app/sentry-ansible.tar` loop, with a re-check after loading to determine whether to print the warning.

### 4. `PlaybookSuggestions.jsx` (both directories)
Extracted during refactor but the `Play` icon import was not carried over from the parent `AiChat.jsx`. Added `{ Zap, Play }` to the lucide-react import statement.

## Usage

### Prerequisites for frontend dev stack
When running `npm run dev` in `frontend/`, ensure the backend services are also running:
```bash
# Terminal 1: watchman API
cd watchman && uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# Terminal 2: syslog-ng container
podman-compose up syslog-ng

# Terminal 3: frontend dev server
cd frontend && npm run dev
```

### Rebuild all containers (podman stack)
```bash
python watchman/scripts/container_manager.py build all
python watchman/scripts/container_manager.py down
python watchman/scripts/container_manager.py up
```

## Design Notes

- **`--pull=never` vs fixing the root cause**: The root cause is that `sentry-ansible.tar` was never generated during the build. Adding `--pull=never` is a defense-in-depth measure — even if the tar is missing, podman will fail immediately with a clear error rather than attempting to pull from `localhost` as a registry.
- **Why the command-center (port 3000) worked during refactor**: The podman stack serves a pre-built `dist/` from the command-center container. The `dist/` was built before the refactor removed the inline components, so the old working code was served. The frontend dev server reads source files directly, exposing the missing import immediately.
- **Why keep both frontend directories**: `command-center/` is the production target (nginx-served in podman). `frontend/` enables quick host-based development. They will be unified once the project stabilizes.
